

================================================================================
 BASE
================================================================================

  Base URL      : http://localhost:4000   (port from PORT env, default 4000)
  Route prefix  : /stock-correction
                  NOTE: there is NO /api or /v1 prefix. InversifyExpressServer
                  is built without a root path.
  Auth          : Required on every endpoint (deserializeUser, requireUser)
  Content-Type  : application/json


--------------------------------------------------------------------------------
 AUTH HEADER
--------------------------------------------------------------------------------

  Authorization: Bearer <access_token>

  The access_token cookie is also accepted as a fallback.

  IMPORTANT: The logged-in user is taken from the token, NOT from the body.
    - createdBy  (on submit)          -> set from res.locals.user.id
    - approvedBy (on approve/reject)  -> set from res.locals.user.id


--------------------------------------------------------------------------------
 STANDARD RESPONSE ENVELOPE
--------------------------------------------------------------------------------

  Success:
      { "status": "success", "data": { ... } }

  Success with a message (approve / reject only):
      { "status": "success", "message": "Correction approved", "data": { ... } }

  Error (from the global handler in src/app.ts):
      4xx ->  { "status": "fail",  "message": "Correction already processed" }
      5xx ->  { "status": "error", "message": "Internal Server Error" }


--------------------------------------------------------------------------------
 ENUMS
--------------------------------------------------------------------------------

  CorrectionType    = "physical_count" | "damage_write_off" | "system_error"
                      | "other"

  CorrectionStatus  = "pending" | "approved" | "rejected"

  DumpReason        = "damage" | "expiry" | "pest" | "fire" | "other"


--------------------------------------------------------------------------------
 NOTE ON NUMBERS
--------------------------------------------------------------------------------

  All money/quantity columns are Postgres "decimal", so they come back as
  STRINGS ("100.00"), not numbers.

  The only exception is GET /stock-correction/stock/:inventoryStockId, where
  "currentStock" is explicitly passed through Number() by the service.


================================================================================
 ENDPOINT SUMMARY
================================================================================

  #  METHOD  ENDPOINT                                     PURPOSE
  -  ------  -------------------------------------------  ------------------------
  1  POST    /stock-correction                            Submit new correction
                                                          (status = pending)
  2  GET     /stock-correction/pending                    List all pending
  3  GET     /stock-correction/:id                        Get one correction
  4  GET     /stock-correction/stock/:inventoryStockId    Current stock + history
  5  PATCH   /stock-correction/:id/approve                Approve - THIS updates
                                                          inventory_stock
  6  PATCH   /stock-correction/:id/reject                 Reject - no stock change


================================================================================
 1. SUBMIT A CORRECTION
================================================================================

  METHOD    : POST
  ENDPOINT  : /stock-correction
  SUCCESS   : 201 Created


--------------------------------------------------------------------------------
 REQUEST BODY
--------------------------------------------------------------------------------

  FIELD               TYPE            REQUIRED   NOTES
  ------------------  --------------  ---------  --------------------------------
  inventoryStockId    string (uuid)   YES        The inventory_stock row being
                                                 corrected
  correctionType      CorrectionType  YES        See enum above
  physicalQty         number          YES (*)    Actual counted quantity
  correctionAmt       number          no         Adjustment to inwardAmt.
                                                 Default 0
  reason              string          no         Free text
  correctionDate      string (date)   no         Parsed via new Date()

  dumpQty             number          YES (**)   Must be > 0
  dumpAmt             number          no         Value of write-off. Default 0
  dumpReason          DumpReason      no
  dumpRemarks         string          no
  dumpDate            string (date)   no

   (*) See the two calculation paths below - ignored for damage_write_off.
  (**) Required only when correctionType = "damage_write_off".


--------------------------------------------------------------------------------
 !! TWO DIFFERENT CALCULATION PATHS !!
--------------------------------------------------------------------------------

  CASE A -- correctionType = "damage_write_off"

      physicalQty     = stock.inwardQty - dumpQty     <- computed by the SERVER
      correctionDelta = -dumpQty                      <- always negative

      The physicalQty sent in the body is IGNORED for this type; the server
      overwrites it. dumpQty must be > 0 or the request fails with 400.


  CASE B -- every other type (physical_count, system_error, other)

      physicalQty     = body.physicalQty              <- taken as-is
      correctionDelta = physicalQty - stock.inwardQty <- may be + or -


--------------------------------------------------------------------------------
 EXAMPLE A - PHYSICAL COUNT (system says 500, actually counted 480)
--------------------------------------------------------------------------------

  {
    "inventoryStockId": "3f9a1c2e-77b4-4d55-9a11-0c6f2b8e4d10",
    "correctionType": "physical_count",

    "correctionAmt": -1200,
    "reason": "Monthly physical verification - 20 kg short",
    "correctionDate": "2026-08-19"
  }

--------------------------------------------------------------------------------

      The subset of "corrections" where status === "pending". It is a FILTERED
      COPY, not a separate query - so rows appear in BOTH arrays.

================================================================================
 5. APPROVE A CORRECTION
================================================================================

  METHOD    : PATCH
  ENDPOINT  : /stock-correction/:id/approve
  SUCCESS   : 200 OK

  This is the ONLY endpoint that writes to inventory_stock. It runs inside a
  TypeORM transaction and is guarded by a status check, so a correction can be
  applied only once.

  PATH PARAM    TYPE            NOTES
  ------------  --------------  ------------------------------------------------
  id            string (uuid)   The correction id


--------------------------------------------------------------------------------
 REQUEST BODY
--------------------------------------------------------------------------------

  FIELD      TYPE      REQUIRED   NOTES
  ---------  --------  ---------  -----------------------------------------------
  remarks    string    no         Approver's note. Body may be {} or omitted

  {
    "remarks": "Verified against weighbridge slip"
  }


--------------------------------------------------------------------------------
 WHAT IT CHANGES ON inventory_stock
--------------------------------------------------------------------------------

      inwardQty += correctionDelta          // ALWAYS
      inwardAmt += correctionAmt            // only when correctionAmt !== 0

      // additionally, ONLY when correctionType === "damage_write_off":
      dumpQty   += correction.dumpQty
      dumpAmt   += correction.dumpAmt

  Then on the correction itself:
      status      -> "approved"
      approvedBy  -> <token user>
      approvedAt  -> now
      remarks     -> if supplied

  The stock update and the status flip commit TOGETHER. If either fails, both
  roll back.


--------------------------------------------------------------------------------
 RESPONSE 200
--------------------------------------------------------------------------------

  {
    "status": "success",
    "message": "Correction approved",
    "data": {
      "id": "a1b2c3d4-5e6f-4a7b-8c9d-0e1f2a3b4c5d",
      "status": "approved",
      "systemQty": "500.00",
      "physicalQty": "480.00",
      "correctionDelta": "-20.00",
      "correctionAmt": "-1200.00",
      "correctionType": "physical_count",
      "remarks": "Verified against weighbridge slip",
      "approvedBy": { "id": "u2000000-..." },
      "approvedAt": "19-08-2026 04:10 PM",
      "inventoryStock": {
        "id": "3f9a1c2e-77b4-4d55-9a11-0c6f2b8e4d10",
        "inwardQty": "480.00",
        "inwardAmt": "28800.00",
        "dumpQty": "0.00",
        "dumpAmt": "0.00"
      }
    }
  }

  NOTE: The returned "data" is the CORRECTION object. approvedBy is { id } only.
        inventoryStock reflects the ALREADY-UPDATED figures.


--------------------------------------------------------------------------------
 ERRORS
--------------------------------------------------------------------------------

  CODE   MESSAGE                        WHEN
  -----  -----------------------------  ---------------------------------------
  400    Correction not found           Bad id
  400    Correction already processed   status is not "pending"
                                        (this is the double-apply guard)


================================================================================
 6. REJECT A CORRECTION
================================================================================

  METHOD    : PATCH
  ENDPOINT  : /stock-correction/:id/reject
  SUCCESS   : 200 OK

  NO STOCK CHANGE OF ANY KIND. Only the correction row is updated.

  PATH PARAM    TYPE            NOTES
  ------------  --------------  ------------------------------------------------
  id            string (uuid)   The correction id


--------------------------------------------------------------------------------
 REQUEST BODY
--------------------------------------------------------------------------------

  Same as approve - remarks is optional.

  {
    "remarks": "Recount requested - figures do not match the gate register"
  }

  Sets:
      status      -> "rejected"
      approvedBy  -> <token user>
      approvedAt  -> now
      remarks     -> if supplied

  NOTE: The approvedBy / approvedAt columns are REUSED for rejection. There are
        no separate rejectedBy / rejectedAt columns.


--------------------------------------------------------------------------------
 RESPONSE 200
--------------------------------------------------------------------------------

  {
    "status": "success",
    "message": "Correction rejected",
    "data": {
      "id": "a1b2c3d4-5e6f-4a7b-8c9d-0e1f2a3b4c5d",
      "status": "rejected",
      "remarks": "Recount requested - figures do not match the gate register",
      "approvedBy": { "id": "u2000000-..." },
      "approvedAt": "19-08-2026 04:15 PM"
    }
  }


--------------------------------------------------------------------------------
 ERRORS
--------------------------------------------------------------------------------

  CODE   MESSAGE
  -----  -----------------------------
  400    Correction not found
  400    Correction already processed


================================================================================
 TYPICAL FLOW
================================================================================

     POST /stock-correction
         |                                    status = pending
         v
     GET /stock-correction/pending
         |                                    approver sees it in the queue
         v
     PATCH /stock-correction/:id/approve  --> inventory_stock updated
         |                                    status = approved
         |   OR
         |
     PATCH /stock-correction/:id/reject   --> nothing touched
         |                                    status = rejected
         v
     GET /stock-correction/stock/:inventoryStockId
                                              verify new figures + history


================================================================================
 THINGS TO BE AWARE OF
================================================================================

  1. NO ROLE RESTRICTION ON APPROVE / REJECT
     Both endpoints only require a logged-in user (requireUser). Any
     authenticated user can approve their own correction. There is no
     approval-flow / documents integration on this module, unlike the other
     inventory documents.

  2. GET /pending IS UNPAGINATED
     It returns every pending row with 6 relations eagerly joined. It will get
     slow as the table grows.

  3. DECIMALS ARRIVE AS STRINGS
     Use Number(...) on the frontend before doing arithmetic.
     Example:  "480.00" + 20   gives   "480.0020"

  4. physicalQty IS REQUIRED BY THE DTO EVEN FOR damage_write_off
     ...where the server ignores it. Send 0.

  5. NO UPDATE OR DELETE ENDPOINT
     A correction cannot be edited or removed once submitted - only approved
     or rejected.

  6. correctionAmt IS NOT AUTO-DERIVED
     If you do not send it, inwardAmt is left untouched even when inwardQty
     changes, so quantity and value can drift apart. The caller must compute it.
